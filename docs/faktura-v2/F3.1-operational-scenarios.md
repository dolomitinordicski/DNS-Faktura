# DNS Faktura v2 — F3.1 Operational Scenarios

These scenarios are executable domain checks. They describe expected DNS behavior independently of UI, Firebase and Foundation.

## S01 — Partial confirmation batch

Order:
- 500 wristbands
- 1,000 tickets
- 1,500 Pocketfolders

DNS creates Confirmation A with wristbands + tickets only.

Expected:
- Confirmation A contains exactly 2 lines.
- Pocketfolder remains outside the batch.
- Original Order remains unchanged.

## S02 — Unchanged confirmation

Area receives:
- wristbands: 500
- tickets: 1,000

Area accepts both unchanged.

Expected:
- Confirmation -> CONFIRMED
- confirmedQuantity = proposedQuantity
- confirmedBy and confirmedAt are recorded.

## S03 — Area requests quantity change

Area changes wristbands from 500 to 450.

Expected:
- Confirmation -> CHANGE_REQUESTED
- no line becomes economically confirmed yet
- DNS must explicitly approve.

After DNS approval:
- Confirmation -> CONFIRMED
- confirmedQuantity(wristbands) = 450
- original orderedQuantity remains 500.

## S04 — Billing uses confirmed quantity

Order wristbands = 500.
Confirmed wristbands = 450.
Rate = EUR 0.159 / piece.

Expected billing:
- quantity = 450
- not 500
- amount = EUR 71.55.

## S05 — Multiple confirmation batches

One order may be split into:
- Confirmation A: wristbands + tickets
- Confirmation B: Pocketfolders

Expected:
- both reference the same Order
- each contains only selected lines
- billing lines preserve Confirmation IDs as source lineage.

## S06 — Manual service lines

Drei Zinnen billing sheet may contain:
- Grafik: 6.5 hours × EUR 65
- Kartografie: 3 hours × EUR 80
- Korrekturen: 1 flat × EUR 120

Expected:
- manual lines do not become catalog items automatically
- common formula quantity × unitPrice applies
- custom source IDs remain local to Faktura.

## S07 — Prepayment gate

Confirmed material order is invoiced and marked prepaymentRequired.

Expected:
- OPEN payment -> delivery release false
- PAID payment -> delivery release true.

## S08 — Partial delivery

Confirmed = 450.
Delivered = 400.

Expected:
- remaining = 50
- delivery status = PARTIAL.

When delivered = 450:
- remaining = 0
- status = DELIVERED.

## S09 — Guard against over-delivery

Confirmed = 450.
Attempt delivered = 451.

Expected:
- rejected by domain engine.

## S10 — Billing lifecycle

Expected:
DRAFT -> READY -> INVOICED

Invalid transitions are rejected.
