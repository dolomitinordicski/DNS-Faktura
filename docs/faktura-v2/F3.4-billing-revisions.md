# DNS Faktura v2 — F3.4 Billing Sheet Revisions & Immutability

## Principle

A Billing Sheet in READY or INVOICED state is a frozen historical snapshot.

It is never reopened and never edited in place.

If any source changes after READY/INVOICED, Faktura creates a new Billing Sheet revision.

## Lifecycle

DRAFT -> READY -> INVOICED

Only DRAFT is editable.

READY:
- source values and prices are frozen
- the sheet is ready to become the basis for invoicing

INVOICED:
- the sheet represents the exact billing basis used for an issued invoice
- it must remain unchanged permanently

## Revision rule

A revision may be created only from READY or INVOICED.

The new revision:
- has a new id
- revision = previous revision + 1
- status = DRAFT
- has supersedesBillingSheetId = previous id
- requires an explicit revisionReason
- copies or rebuilds lines from current valid sources

The previous sheet is not mutated.

## Example: confirmation correction after READY

Billing Sheet B1 rev.1 READY:
- 300 wristbands × EUR 0.159 = EUR 47.70

Confirmation is corrected to 250.

Do not edit B1.

Create:
Billing Sheet B2 rev.2 DRAFT
- supersedes B1
- 250 wristbands × EUR 0.159 = EUR 39.75

B1 remains an exact historical snapshot.

## Example: source correction after INVOICED

Billing Sheet B1 rev.1 INVOICED was used to issue an invoice.

A later correction is discovered.

Do not alter B1 and do not silently reinterpret the invoice.

Create a new DRAFT revision B2.

Any external accounting consequence (credit note, replacement invoice, etc.) remains outside Faktura v2 and must be handled by the official accounting system.

## Source lineage

Every BillingLine keeps:
- sourceType
- sourceId
- sourceRevision
- sourceDocument where available

This makes it possible to explain exactly which Confirmation, FAIR revision, IDM source, price revision or manual source produced a frozen billing line.

## Concurrency / persistence rule

When Firebase persistence is added, creation of a billing revision must verify transactionally that:
- the original revision is still the latest accepted base
- revision number is sequential
- organization and season match
- the new revision starts as DRAFT

No READY or INVOICED document may be patched through a generic edit operation.
