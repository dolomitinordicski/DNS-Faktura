# DNS Faktura v2 — F3.5 Source Freshness / Stale Detection

## Goal

A Billing Sheet must know whether its source references still represent the latest valid revisions.

This check is independent from UI and persistence.

## States

For every BillingLine:

- FRESH — the referenced source revision is still current
- STALE — a newer source revision exists
- MISSING_SOURCE — the referenced source can no longer be resolved

## Example

Billing line:
- sourceType = ORDER_CONFIRMATION
- sourceId = confirmation-c1
- sourceRevision = 1

Current source registry:
- confirmation-c1 currentRevision = 2

Result:
STALE

The Billing Sheet must not silently update the line. A new Billing Sheet revision must be created from the newer source.

## Sources covered

The mechanism is generic and applies to:
- ORDER_CONFIRMATION
- FAIR
- IDM
- MANUAL_SERVICE when a revisioned manual source is used

Rate freshness may later be exposed through the same mechanism or a dedicated rate-source contract.

## READY guard

Before a DRAFT Billing Sheet may transition to READY, source freshness will be checked.

A sheet with STALE or MISSING_SOURCE references cannot become READY.

READY and INVOICED sheets remain immutable historical snapshots even if they later become stale relative to newer sources.

## Important distinction

STALE does not mean the historical snapshot is wrong.

It means:
- there is now a newer source revision
- the frozen READY/INVOICED snapshot still accurately represents what was used at that time

Freshness is therefore a workflow signal, not a reason to mutate history.
