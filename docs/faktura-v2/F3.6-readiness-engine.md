# DNS Faktura v2 — F3.6 Readiness Engine

## Purpose

DRAFT -> READY is a guarded business transition, not a manual status toggle.

A Billing Sheet is READY only when every mandatory condition is satisfied.

## Readiness checks

The engine checks:

1. the sheet is not empty
2. configured mandatory source types are present
3. every line has valid quantity
4. every line has a valid unit price
5. every line has a valid amount
6. every referenced source can still be resolved
7. no referenced source is stale
8. every ORDER_CONFIRMATION line points to an existing CONFIRMED Confirmation
9. the Confirmation revision equals the revision frozen into the BillingLine

## Required source types

Required source types are supplied as policy/configuration rather than hard-coded globally.

Example:
- an organization may require FAIR
- IDM only applies to participating areas
- ORDER_CONFIRMATION applies only where confirmed material orders exist

This keeps the readiness engine generic and avoids inventing billing positions that do not apply.

## Output

evaluateBillingReadiness returns:
- ready: boolean
- issues[]

The transition helper markBillingSheetReadyWhenValid refuses READY when any issue exists.

## Principle

The UI may explain readiness issues later, but it may not override them silently.
