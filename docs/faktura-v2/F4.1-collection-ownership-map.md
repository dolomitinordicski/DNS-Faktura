# DNS Faktura v2 — F4.1 Collection & Ownership Map

## Faktura-owned collections

| Collection | Owner | Mutability | Primary scope |
|---|---|---|---|
| fakturaConfirmations | Faktura | lifecycle + immutable history | season + organization + order |
| fakturaBillingSheets | Faktura | DRAFT mutable, READY/INVOICED frozen | season + organization |
| fakturaPayments | Faktura | operational status | billingSheetId |
| fakturaDeliveries | Faktura | operational delivery progress | billingSheetId + orderId |
| fakturaEvents | Faktura | append-only | entity + organization + season |
| fakturaConfirmationTokens | Faktura | security lifecycle | confirmationId |

## External collections / sources

| Source | Owner | Faktura access |
|---|---|---|
| ticketOrders | DNS Data Entry | read |
| ticketOrderLines | DNS Data Entry | read |
| FAIR source | FAIR | read |
| IDM source | DNS/shared config | read |
| organizations | DNS_Core/shared data | read |
| seasons | DNS_Core/shared data | read |
| orderCatalogItems | DNS_Core/shared data | read |
| billingRateConfigs | billing/shared source | read |

## Hard rule

Faktura v2 never writes into upstream order, FAIR, IDM, organization, season or catalog records.

If Faktura needs to preserve a business state from an external source, it stores:
- sourceType
- sourceId
- sourceRevision
- sourceDocument
- frozen quantity/price/amount in its own snapshot

## Public confirmation

Public confirmation access is mediated by fakturaConfirmationTokens.

The public client must never query fakturaConfirmations directly by arbitrary id.

Token resolution returns only:
- allowed confirmation
- display payload
- response capability

No list/query permission is exposed publicly.
