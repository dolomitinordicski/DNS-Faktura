# DNS Faktura v2 — F5.1 / F5.2 Live Firebase Source Adapters

## Scope

This phase connects the v2 source contracts to the real Firebase sources without touching UI, Foundation or Faktura-owned persistence.

## F5.1 Orders / Data Entry

Source project: DNS Core.

Read-only collections:
- ticketOrders
- ticketOrderLines
- orderCatalogItems

The adapter:
- loads only the requested season
- exposes only SUBMITTED orders to the v2 domain contract
- preserves original order ids and catalog item ids
- maps Data Entry quantity -> orderedQuantity
- resolves category and display label from orderCatalogItems
- does not write to Data Entry
- does not infer billing eligibility from old v1 statuses

## F5.2 FAIR

Source project: fair-modell.

Read-only document:
- fairModel/ws-2026-27 for season 2026-27
- otherwise fairModel/{seasonId}

The adapter reads:
- billing.organizations[].organizationId
- billing.organizations[].totalAmount
- source metadata

Faktura does NOT recalculate FAIR distribution and does not use distributionKey for billing.

### Revision compatibility

The current FAIR payload does not yet publish a dedicated business revision.

Revision resolution order:
1. billing.revision, when introduced
2. root revision, when introduced
3. legacy clientUpdatedAt timestamp

clientUpdatedAt is therefore only a monotonic compatibility surrogate for source freshness.

If none exists, the adapter throws FAIR_REVISION_MISSING rather than inventing a revision.

## Architecture

Domain contracts:
- DataEntryOrderSource
- FairContributionSource

Pure mapping:
- sourceAdapters.ts

Firebase-specific read layer:
- firebaseBackends.ts

Live composition:
- liveSources.ts

This preserves dependency direction:

Firebase -> backend -> adapter -> domain contract

The domain engine has no Firebase dependency.
