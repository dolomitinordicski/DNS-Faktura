# DNS Faktura v2 — F5.7 BillingSheet Persistence

## Scope

F5.7 implements real Faktura-owned persistence for BillingSheet DRAFT and the DRAFT -> READY transition.

Collections:
- `fakturaBillingSheets`
- `fakturaEvents`

No UI/Foundation dependency is introduced.

## DRAFT persistence

`persistBillingDraft()` converts an assembled BillingSheet into a persistence record with:
- createdAt
- createdBy
- updatedAt
- updatedBy

The Firestore repository:
- accepts only DRAFT
- never overwrites READY/INVOICED
- rejects scope/revision mismatch on an existing DRAFT

## READY transaction

The application service first executes the complete F5.6 readiness gate.

The repository transaction then reads the persisted BillingSheet and validates:
- document exists
- status is still DRAFT
- `updatedAt === expectedUpdatedAt`

If the DRAFT changed after readiness evaluation, transition fails with:

`BILLING_DRAFT_CHANGED`

On success one Firestore transaction writes:
1. BillingSheet DRAFT -> READY
2. `readyAt`
3. updatedAt / updatedBy
4. append-only `BILLING_READY` audit event

The audit event id is deterministic per BillingSheet revision, preventing a second READY event for the same revision.

## INVOICED transaction

The concrete repository also implements READY -> INVOICED atomically with its `BILLING_INVOICED` audit event.

This is available for the next application phase but is not yet wired into the F5.7 application workflow.

## Concurrency boundary

The BillingSheet document and audit event are fully atomic because they live in the same Firebase project.

External sources (for example FAIR in a separate Firebase project) cannot participate in the same Firestore transaction.

Therefore:
- external source freshness is evaluated immediately before the READY transaction
- the BillingSheet freezes the exact source and rate revisions that were validated
- DRAFT concurrency is guarded transactionally through `expectedUpdatedAt`

A future cross-project source change after a sheet is frozen is a new source revision, not an in-place mutation of the frozen BillingSheet.

## Safety

CI tests use in-memory repository doubles.

No production Faktura v2 documents are created by tests or by this implementation step.
