# DNS Faktura v2 — F6.4 MANUAL_SERVICE Application Workflow

## Purpose

F6.4 completes the real application path for one-off manual/service billing lines.

A manual/service line is owned by Faktura and may be edited only while its BillingSheet is in DRAFT.

No separate persistent source collection is required for simple one-off entries.

## Canonical workflow

Supported application commands:

- addManualService()
- updateManualService()
- removeManualService()

All commands require:
- billingSheetId
- lineId
- actorId
- occurredAt
- expectedUpdatedAt

ADD and UPDATE also require:
- description
- quantity
- unit
- customUnitLabel? when unit = custom
- unitPrice
- prepaymentRequired?
- notes?

## Source lineage

For one-off manual/service lines, the application derives:

`sourceId = manual:{billingSheetId}:{lineId}`

The caller does not supply sourceId.

This prevents a manual line from impersonating FAIR, IDM or another external source.

Simple one-off manual lines have no sourceRevision and are self-contained once frozen.

## Validation

The existing domain validation remains authoritative:

- quantity finite and >= 0
- unitPrice finite and >= 0
- flat unit requires quantity = 1
- custom unit requires customUnitLabel

F6.4 adds:
- non-empty description
- non-empty lineId
- add rejects duplicate line id
- update/remove reject missing line
- update/remove reject non-MANUAL_SERVICE line
- line id may not change during update

## Persistence

`BillingSheetRepository.mutateManualServiceTransaction()` supports:

- ADD
- UPDATE
- REMOVE

The Firestore implementation:

1. reads current BillingSheet
2. requires DRAFT
3. verifies `updatedAt === expectedUpdatedAt`
4. applies domain mutation
5. recalculates totalAmount from all BillingLines
6. writes updatedAt / updatedBy
7. appends audit event
8. writes BillingSheet + event in one transaction

## Audit events

- BILLING_MANUAL_LINE_ADDED
- BILLING_MANUAL_LINE_UPDATED
- BILLING_MANUAL_LINE_REMOVED

Each audit event records:
- operation
- lineId
- totalAmountBefore
- totalAmountAfter

The event is written atomically with the BillingSheet mutation.

## Immutability boundary

Manual/service lines cannot be mutated after BillingSheet leaves DRAFT.

READY and INVOICED remain frozen historical snapshots.

Corrections after READY/INVOICED require a new BillingSheet revision, exactly like changes from FAIR, IDM, Confirmation or commercial rates.

## Protection of non-manual lines

The manual workflow cannot update or remove:
- FAIR
- IDM
- ORDER_CONFIRMATION

Those lines remain source-owned and may change only by rebuilding/revising the DRAFT from their canonical sources.

## Reusable manual sources

`fakturaManualSources` remains optional for future reusable/revisioned service sources.

F6.4 does not create or require that collection.

Rule:
- one-off service -> embedded MANUAL_SERVICE line
- reusable governed source with independent lifecycle -> future revisioned fakturaManualSources record

## Result

After F6.4, Faktura v2 has a complete backend/application workflow for manual billing entries without introducing a duplicate catalog or source system.
